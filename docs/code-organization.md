## Code organization

### Zod validation schemas

Every zod validation schema in the project lives in `app/validationSchemas.ts`. Don't define schemas inside components, pages, or other files; import them from `app/validationSchemas.ts`.

### Where components live

A component is placed based on where it is used:

- **Used in only one route** → right next to that route's `page.tsx`, inside that route folder.
- **Used in a route and its nested routes** → in the parent route folder (the highest route that uses it). The nested routes import it from there; don't copy it or move it down.
- **Used in multiple unrelated routes** (not one parent/child tree) → in `app/components/`.

Examples:

- `app/(app)/schedule/ScheduleCard.tsx` is used only by `app/(app)/schedule/page.tsx`, so it stays in `app/(app)/schedule/`.
- `app/(app)/classes/ClassForm.tsx` is used by both `app/(app)/classes/new/page.tsx` and `app/(app)/classes/[id]/edit/page.tsx`, so it stays in `app/(app)/classes/` and both nested routes import it from there.
- `app/components/SubjectBadge.tsx` is used by `/subjects`, `/classes` and `/schedule`, so it goes in `app/components/`.

A route group folder (`(marketing)`, `(auth)`, `(app)`) is not a route: routes that merely share a group are unrelated, so a component they share goes in `app/components/`, not in the group folder.

When a component's usage changes (e.g. a page-only component starts being used in another unrelated route), move it to the correct location and update the imports in the same change.

### Pages lay out components

A route's `page.tsx` is primarily responsible for laying out components: fetching the data the page needs and arranging the components on the page.

Don't put large blocks of UI, form logic, or interactive state directly in `page.tsx`. Break the page into well-named, focused components (e.g. a header, a list, a card, a form, an empty state), each with a single clear responsibility.

Keep components small and readable. If a component grows large or handles several unrelated things, split it further.

### shadcn components are an exception

UI primitives generated by the shadcn CLI stay where the CLI puts them at the repo root: `components/ui/` for shadcn's own, and the registry's folder for a third-party registry (`components/reui/` for the phone input). The rules above apply to the app's own components, not to generated primitives.
